## 2. 核心诊断

1. **任务顺序错了。** 创建配置压过“选择一个已就绪 Trial 并开始对话”，真正要验收的任务被推到首屏以下。
2. **详情不是工作区。** Trial 没有 URL 深链，刷新会丢失当前选择；左侧已选状态和中部详情也缺少强关联。
3. **同一个状态被拆成三套。** 生命周期、请求状态、停止标记分别显示，用户需要自己拼出“现在能不能发、为什么不能发、下一步做什么”。
4. **错误离操作太远。** 顶部错误条与实例绑定、发送消息、结束回收等操作相距很远，也没有稳定的恢复路径。
5. **回收过程被压缩。** 结束按钮直接发请求，没有确认实例归属、进程退出、实例删除、租约释放这些事实层级。
6. **移动端不是简单缩放。** 记录表横向溢出，聊天与回收按钮极深；移动端需要队列抽屉、状态条和底部会话。

## 3. 三个方向

### F1 · 试用工作台

- 视觉主张：现有 ModelForge 浅色工作台的连续演进，不换品牌、不换导航。
- 核心流程：左侧 Trial 队列 → 中部对话验收 → 右侧运行对象、指纹、回收倒计时和结束动作。
- 合并点：吸收 F2 的固定业务问题，吸收 F3 的进程退出 / 实例回收回执。
- 优点：迁移成本最低；符合现有产品语言；一个屏幕回答“用哪个 Adapter、服务能否用、下一步做什么”。
- 代价：三栏在 1024px 需要重排，右侧上下文必须以抽屉或折叠区承接。
- 适用：**推荐作为生产落地主路径。**

### F2 · 对话验收实验室

- 视觉主张：更接近评测工具，深靛色导航 + 白底会话 + 右侧人工判断栏。
- 核心流程：固定问题 → 生成 → 有用 / 偏题 / 不安全标记 → 结束验收。
- 优点：验收意识最强，最适合回归对比多个 Adapter。
- 代价：对“创建、绑实例、回收”这类平台任务偏重；人工评级目前只是前端演示，不应冒充已落库能力。
- 适用：未来作为 F1 的「验收实验」子视图。

### F3 · 运行驾驶舱

- 视觉主张：深色控制台、生命周期轨道、运行事实和回收回执。
- 核心流程：队列 → 准备 / 就绪 → 对话 → 停止 → 进程退出 → 实例删除 → 租约释放。
- 优点：状态最透明，适合排查实例未回收、进程退出、请求阻塞等异常。
- 代价：整站深色与 ModelForge 现有浅色工作台冲突；实现和长期维护成本最高。
- 适用：只建议作为高级运行视图，不推荐整站切换。

## 4. 最终决策

**F1 为生产实现基线，融合 F2 的业务验收问题与 F3 的回收事实链。**

不把三套方案平均混合，而是明确分层：

- 主工作区：F1。
- 未来验收子流程：F2。
- 高级生命周期检查器：F3。

F1 的交互已经包含“合并优化”版本：

- 创建 Trial 改为弹层，不占首屏。
- 左侧队列固定当前 Trial，右侧持续显示基座 / Adapter 指纹与实例。
- 固定业务问题用于避免随机聊天，但不增加正式验收写库承诺。
- 等待实例、准备中、失败、回收中、已结束都会替换同一工作区，而不是另开页面。
- 结束试用必须经过确认；回收后显示进程、实例、租约三层结果。

## 6. 状态与交互覆盖

三套原型都支持以下 `?scenario=` 状态：

- `empty` 空状态
- `loading` 加载中
- `waiting` 等待手动实例
- `preparing` 准备推理
- `ready` 可试用
- `streaming` 流式生成
- `blocked` 失败 / 需要处理
- `stopping` 回收中
- `stopped` 回收成功
- `create` 创建弹层

可演示的真实交互：

- Adapter 必选校验
- 创建后进入等待实例
- 绑定实例与授权清理
- 固定问题填入
- 流式生成
- 停止生成并保留部分输出
- 失败重试
- 清空页面会话
- 结束确认 → 回收中 → 回收成功
- 移动端队列抽屉与运行详情抽屉

状态预览器位于右下角；移动端上移到输入区上方，避免遮挡发送按钮。
