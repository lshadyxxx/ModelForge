# Serving F1.1 执行计划

## 1. 目标

把现有纵向堆叠的 Serving 页面重构为 F1.1 工作台：

- 左侧：可快速切换和识别的 Trial 队列。
- 中部：当前 Trial 的会话、生成控制和错误恢复。
- 右侧：当前 Adapter、基座、实例、空闲期限、准备检查和回收动作。
- 创建：独立弹层，不占据工作区首屏。
- 回收：二阶段确认，并按真实事实显示进程、实例、租约状态。

目标不是“换一套皮肤”，而是把用户的核心任务固定为一句话：

> 选一个 Trial，确认它绑定了什么，完成一次真实对话，然后安全地结束。

## 2. 成功标准

### 用户体验

- 用户进入 Serving 后无需先阅读 11 个常驻实例表单控件（含 10 个持久字段）。
- 选择 Trial 后，URL 可复制，刷新后恢复当前 Trial。
- 一屏内能回答：当前 Adapter 是什么、服务是否可用、能不能发消息、失败后做什么、实例何时回收。
- 生成中、停止中、未知、回收中和已回收不会显示成同一状态。
- 桌面 1440、笔记本 1024、平板 768、手机 390 均无横向溢出。

### 工程

- `npm test` 和 `npm run build` 通过。
- 相关后端测试通过；新增只读回执投影不改变写入状态机。
- 不新增数据库迁移。
- 不新增运行时依赖，除非单独提出并获批。
- 页面隐藏时停止轮询；轮询请求不重叠；SSE 停止后仍有可解释状态。

### 证据

- 每个票据有独立实现摘要和验证记录。
- 浏览器流程覆盖创建、等待实例、绑定、准备、发送、停止生成、清空、结束、回收成功。
- 明确区分“前端模拟”“API 合同测试”“真实 GPU 验证”。

## 3. 范围

### P0：形成可替换旧页面的完整版本

P0 完成时应具备：

- Trial 路由与统一状态模型。
- F1.1 桌面三栏工作台。
- 创建弹层与手动实例绑定工作区。
- 对话、流式输出、停止生成、清空会话。
- 结束确认和真实回收回执。

### P1：质量收口

P1 完成时应具备：

- 队列优先级、过滤、搜索和可操作排序。
- 移动端抽屉式队列/运行事实。
- 完整键盘、ARIA、焦点、触控和 reduced-motion 行为。
- 浏览器验收、视觉证据和残余样式清理。
- 自动提醒逻辑的失败恢复信息：过期数据、重连、局部错误。

### P2：可选增强

- F2 验收实验子视图。
- F3 高级运行检查器。

P2 只有在 P0/P1 验收完成后另开范围，不与主工作台混在同一批提交中。

## 4. 明确非目标

- 不持久化聊天历史。
- 不实现多用户、权限、远程访问或生产部署。
- 不更改单 GPU 租约、Worker 生命周期或数据库状态枚举。
- 不新增真实云资源创建能力。
- 不新增基础模型/微调模型并排对比。
- 不把 F2 的人工“有用/偏题/不安全”评级写成正式能力，除非另行实现后端持久化。

## 5. 依赖顺序

```text
P0-01 状态与路由
      |
      +--> P0-02 工作台壳与队列
      |          |
      |          +--> P0-03 创建/绑定
      |          |
      |          +--> P0-04 会话/请求
      |          |
      |          +--> P0-06 回收 UI
      |
      +--> P0-05 回收回执只读 API ----^

P0-02/P0-03/P0-04/P0-06
      |
      +--> P1-01 队列增强
      +--> P1-02 响应式/无障碍
      +--> P1-03 验收与清理
                 |
                 +--> P2-01 验收实验
                 +--> P2-02 运行检查器
```

要求：

- P0-01 先合并，避免多张票各自定义状态。
- P0-05 可与 P0-02 并行，但 P0-06 必须等待 P0-05 的响应字段冻结。
- 默认严格串行 `P0-02 → P0-03 → P0-04 → P0-06`，避免 `Serving.tsx`、`api.ts` 与组合逻辑冲突。
- 若确需并行 P0-03 与 P0-04，只允许一侧修改 `Serving.tsx`，另一侧先提交独立组件与纯函数；共享文件由预定的集成票据统一接入。
- P1 不得在 P0 未完成浏览器闭环前开始“顺手优化”。

## 6. 阶段门

### G0：范围冻结

- 用户确认本计划。
- P0 票据写入本地 issue tracker。
- 文件白名单和禁止项明确。

### G1：状态/路由可验证

- 纯函数测试覆盖所有状态优先级和 URL 往返。
- 不存在两个模块各自维护状态文案。

### G2：F1.1 主流程可用

- 进入页面、选择 Trial、创建、绑定、发送、停止、清空、结束均有可见结果。
- 不依赖修改后端写逻辑。

### G3：回收事实可核对

- API 返回进程、实例、清理、租约四类事实。
- 前端只在事实成立时显示对应绿色完成态。
- 失败和未知状态保留实例 ID、错误码和重试/核对入口。

### G4：质量收口

- 四档视口无横向溢出。
- 键盘操作、焦点顺序、`aria-live` 和触控目标验证。
- 构建、单元测试、后端相关测试、浏览器流程均有证据。

### G5：可选增强

- F2/F3 各自有独立数据来源和验收标准后再启动。

## 7. 预估工作量

以下为相对规模，不是承诺工期。

| 票据 | 规模 | 主要不确定性 |
|---|---:|---|
| P0-01 | M | 状态优先级和现有请求状态语义 |
| P0-02 | L | 现有轮询/加载逻辑迁移，避免功能回退 |
| P0-03 | M | `InstanceFields` 与手动实例确认流程复用 |
| P0-04 | L | SSE、部分输出、取消确认和界面即时反馈 |
| P0-05 | M | 只读租约投影和既有接口兼容性 |
| P0-06 | M | 事实状态与前端文案映射 |
| P1-01 | M | 队列排序和刷新策略 |
| P1-02 | L | 移动端抽屉、焦点管理和可访问性 |
| P1-03 | M | 浏览器证据、样式清理和残余缺陷 |
| P2-01 | L | 评级持久化或明确仅会话内标记 |
| P2-02 | L | 事件流、日志和敏感信息过滤 |

建议节奏：P0 分成 4 个可审查批次；P1 分成 2 个批次；P2 暂不排期。

## 8. 变更与 Git 规则

- 所有工作限于 `<project-root>`。
- 是否 commit 按用户当次命令执行；没有明确授权时只保留工作区改动。任何情况下都不自动 push、建 PR 或部署。
- 不修改其他 worktree。
- 不升级共享依赖，不引入组件库。
- 不删除旧 Serving 组件，直到新页面完成等价验收；删除单独列入 P1-03。
- 不把设计原型 HTML/CSS 原样搬入生产；只迁移视觉 token、结构和交互规则。

## 9. 停止条件

遇到以下任一情况，停止当前票据并上报，不猜测：

- 需要新增数据库字段或迁移才能显示所谓“回执”。
- 需要改变现有 lifecycle/request/stop 枚举才能完成页面。
- 现有 API 返回事实不足以区分进程退出、实例删除和租约释放。
- 需要新增全局依赖或修改后端写入路径。
- 浏览器验收需要激活前台窗口、抢占桌面焦点或越过仓库浏览器边界。
- P0 范围内出现跨模块业务规则迁移。

## 10. 最终交付物

- 正式 Serving 页面及 feature 内组件/CSS。
- 只读回收回执 API 投影。
- 单元测试、API 测试和浏览器验收证据。
- 一份实施记录，说明实际改动、未跑项和残余风险。
- 如 P0/P1 通过，再单独提出 P2 范围，不自动开工。
