# Serving F1.1 视觉系统规格

Status: planning-only  
Direction: Quiet Operational Workbench  
Scope: `features/serving`，沿用 ModelForge 现有品牌与全局框架

## 1. 视觉主张

把 Serving 做成一张克制的模型验收工作台，而不是一组堆叠的管理卡片：

- 结构优先于装饰：用户先看到 Trial、服务状态和会话，再看到技术事实。
- 状态优先于颜色：颜色只强化已解释的状态，不用颜色替代文案。
- 事实优先于乐观反馈：绿色完成态只属于已确认的回收事实。
- 蓝灰主色保持统一，警告和危险色只用于当前操作与异常。
- 数据可核对：ID、指纹、退出码使用等宽字体且可复制。

不采用整站深色驾驶舱，不把每个区块包成圆角阴影卡片，不使用营销页式大标题、渐变背景或装饰性插画。

## 2. 与现有设计规范的关系

生产页面继承现有 ModelForge：

- 字体：`"Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`
- 主蓝：`#245ad0`
- 主蓝 hover：`#1947ae` / `#1948ae`
- 页面背景：`#f5f6f8`
- 表面：`#ffffff`
- 边框：`#e3e7ed`
- 主文字：`#202733`
- 次文字：`#5e6b7c`
- 圆角：控件 6–7px，容器 8px，弹层 10–14px
- 控件最小高度：44px
- 功能文字最小字号：12px

生产实现不得修改全局 token 来迁就 Serving。Serving 专属变量限定在 `.serving-page`：

## 3. 版式与网格

### 桌面

页面头之后是工作台，不再使用“一个表单面板 + 一个列表面板 + 一个详情面板”的纵向堆叠。

```text
┌────────────────────────────────────────────────────────────┐
│ 页面头：推理试用 / 当前状态 / 新建试用                     │
├──────────────┬──────────────────────────┬──────────────────┤
│ Trial 队列   │ 当前 Trial 会话           │ 运行事实         │
│ 约 220px     │ 自适应，最小 400px        │ 约 264px         │
└──────────────┴──────────────────────────┴──────────────────┘
```

建议网格：

```css
.serving-desk {
  display: grid;
  grid-template-columns: minmax(210px, 230px) minmax(400px, 1fr) minmax(250px, 280px);
  gap: 12px;
  align-items: stretch;
}
```

视觉上三栏共用一个大外框或仅用 1px 分隔线，不叠加三层阴影。队列与运行事实内部用留白和分隔线分组。

### 断点

| 视口 | 布局 |
|---|---|
| `>= 1180px` | 三栏工作台；右栏始终可见 |
| `1024–1179px` | 队列 + 会话两栏；运行事实改为右侧抽屉 |
| `768–1023px` | 会话为主；队列和运行事实均为抽屉 |
| `641–767px` | 单栏；顶部工具栏固定入口 |
| `<= 640px` | 单栏；结合 App 现有顶部导航；输入区贴底 |

同时必须验证 App 现有 `1100px` 和 `640px` 断点，不允许新页面在主导航切换时留下断裂网格。

### 间距

- 基础间距单位：4px。
- 常用：8 / 12 / 16 / 20 / 24 / 32。
- 页面左右沿用 App 的 34px；`1024px` 时 24px；`640px` 时 16px。
- 工作台内部栏间距 0–12px；状态块内边距 16–20px；不把所有区域做成独立浮卡。

## 4. 字体层级

| 用途 | 大小 | 字重 | 说明 |
|---|---:|---|---|
| 页面 H1 | 27px | 650 | `推理试用`，延续现有页面 |
| Trial 标题 | 20–22px | 650 | 短 ID + Adapter 角色 |
| 区域标题 | 14–16px | 650 | 队列、会话、运行事实 |
| 正文 | 13–14px | 400 | 对话正文使用 14px |
| 控件/标签 | 12–13px | 600–700 | 不低于 12px |
| 辅助说明 | 12px | 400 | 不低于 12px |
| ID/指纹/时间 | 12px | 400–600 | Cascadia Mono / Consolas |

规则：

- 不使用 9–11px 的功能性文字。
- 大段 ID 使用 `overflow-wrap:anywhere`，但不拆成不可读的单字符列。
- 倒计时、Token 数、退出码使用 `font-variant-numeric: tabular-nums`。
- 页面不出现超过两级标题竞争；Trial 标题是会话区唯一主标题。

## 5. 颜色与语义

### 基础色

| 角色 | 前景 | 背景 | 用途 |
|---|---|---|---|
| 主操作 | `#ffffff` | `#245ad0` | 发送、创建、确认 |
| 次操作 | `#245ad0` | `#ffffff` | 刷新、绑定、清空 |
| 危险操作 | `#a92d33` | `#fff1f1` | 结束并回收、失败 |
| 成功 | `#146a52` | `#eaf7f1` | 已 ready、完整回收 |
| 等待/准备 | `#8c5708` | `#fff7e7` | 等待实例、准备、结束中 |
| 信息 | `#27589c` | `#edf4ff` | 解释、手动创建要求 |
| 中性 | `#5d6a7c` | `#eff2f6` | 已结束但无异常、未知非危险 |

### 状态色使用规则

- 队列项不用整块彩色背景，只用状态点 + 文本 + 可选浅色 chip。
- `blocked` 用红色，不用橙色淡化。
- `ready` 用绿色点，但不把整个页面染绿。
- `ending` 用琥珀色；只有完整回收后变为绿色。
- `ended.incomplete` 用琥珀/红色混合语义，必须显示“待核对”，不能只用绿色勾。
- `request_state=unknown` 用红色或深琥珀色，并与“生成状态未知”文本同时出现。
- 颜色对比度以 WCAG AA 普通文本为最低要求；12px 文字尤其不得使用低对比灰。

## 6. 组件规范

### 6.1 页面头

- 左侧：`推理试用` H1 + 一行说明“选择 Trial，完成真实生成，并确认实例已回收。”
- 右侧：`新建试用` 主按钮；P1 可加入队列搜索。
- 当前 Trial 的短 ID 和状态在进入详情后显示，不在页面头重复大段元数据。
- 不使用大号 hero、功效文案或装饰图形。

### 6.2 Trial 队列

每一项是整块可点击的 button：

```text
fdb5a28c                 ● 可试用
Final · Attempt 7a31    实例 i-8f2...
12:42 更新
```

规格：

- 最小高度 68px。
- 左侧或顶部显示短 ID，使用等宽字体。
- 状态点与短标签同现。
- 当前项：`aria-current="true"`、浅蓝底、左侧 2px 蓝线；不能只靠背景色。
- 组间用 1px 分隔和 8px 留白，不用独立卡片阴影。
- 空状态：说明“完成训练并同步 Best / Final 后，可创建试用。”
- 队列底部显示“显示最近 200 条”或加载/刷新时间。

### 6.3 当前 Trial 标题

一行回答“我在看什么”：

- 短 ID、Adapter 角色、来源 Attempt 短 ID。
- 统一状态标签。
- 复制 Trial ID 图标按钮。
- 右侧“运行事实”入口（非三栏时）。
- 不要把 `state`、`request_state`、`stop_requested` 三个原始枚举并列。

### 6.4 工作区状态页

等待绑定、准备、失败、结束和回收回执使用同一个中栏容器替换会话，不另起页面。

结构：

1. 38–48px 状态图标区；使用单色线性图标，不用 emoji。
2. 状态标题。
3. 1–2 句原因和下一步。
4. 主操作 + 次操作。
5. 可折叠技术事实。

状态页最大宽度约 680px，居中但不垂直铺满整个视口。

### 6.5 会话

- 消息不以左右聊天气泡堆叠；用户消息用浅色块和左侧短标签，模型消息用正文区。
- 每条消息显示角色、时间和“部分输出”标记。
- 模型正文最大宽度约 68–72ch，行高 1.7。
- 生成中在最后一行显示小光标或“正在生成”，符合 `prefers-reduced-motion` 时不动画。
- 自动滚动只在用户靠近底部时发生；用户向上阅读时不得反复拉回。
- 失败消息保留已收到文本；下方提供“重新发送”或“复制文本”，不自动重试。

### 6.6 输入区

```text
┌─────────────────────────────────────────────┐
│ 输入一次真实的验收问题…                     │
│ 固定验收问题  [范围] [退款] [反编造]        │
├─────────────────────────────────────────────┤
│ 生成参数 ▾                    发送 / 停止   │
└─────────────────────────────────────────────┘
```

- 输入框最小高度 88–104px，桌面可 resize。
- 输入区用 1px 边框和 focus ring，不用深色“终端”底。
- 发送按钮与停止按钮占用同一主位，避免同时出现两个强势按钮。
- 固定问题 chip 最小高度 36–40px；功能文字 12px。
- 字符计数在接近上限时出现；常态不显示噪声。

### 6.7 运行事实栏

使用留白和 1px 分隔线分组：

1. **绑定对象**：Adapter、基座、指纹前 12 位、复制完整值。
2. **实例**：实例 ID、状态、计费要求摘要、空闲回收。
3. **准备检查**：运行时、健康、Adapter probe。
4. **危险区**：结束试用。
5. **回执**：结束中或结束后显示生命周期事实。

不得使用 6 个相同卡片堆叠。关键事实标签 12px，值 13px；完整指纹折叠。

### 6.8 生命周期回执

使用纵向事实表，而非模糊进度条：

```text
● 停止请求       已提交
● 推理进程       已退出 · code 0
● 实例删除       已确认
● GPU 租约       已释放
```

规则：

- 已完成：绿色圆点 + 明确过去式。
- 进行中：琥珀色空心圆 + 现在进行时。
- 失败：红色图标 + 错误码 + 下一步。
- 未知：中性问号/空心圆 + “待核对”，不使用绿色。
- 事件时间 12px，不抢主状态。

### 6.9 弹层与抽屉

- 桌面创建弹层宽 720–820px，最大高度 `calc(100vh - 32px)`，头部与底部固定，内容区滚动。
- 确认结束弹层宽 520–560px。
- 移动端使用底部 sheet 或全高对话框；创建表单单列，按钮全宽。
- 使用原生 `<dialog>` 的模态能力；关闭时焦点返回触发按钮。
- 危险确认的初始焦点落在取消按钮，不落在销毁动作。

### 6.10 提示、Toast 与加载

- 页面级错误用带标题的 notice；操作级错误紧贴字段或按钮。
- Toast 仅用于“已复制”“已清空”等短反馈，2–4 秒自动消失。
- 首次加载使用骨架屏，形状与三栏一致。
- 轮询刷新使用 1px 顶部进度线或状态旁的小刷新提示，不整页闪烁。
- 不使用无限旋转的大面积 spinner 覆盖已有内容。

## 7. 图标与数据展示

- 图标统一 18px 线性 SVG，stroke 1.7–1.8，圆角端点。
- 不使用 emoji 代替业务图标。
- 状态点 6–8px，作为文本的补充。
- ID、退出码、Token 数用等宽；长值提供复制。
- 指纹默认显示前 12 位 + 尾 4 位，点击展开完整值。
- 空闲倒计时突出剩余分钟/秒，同时显示预计回收时间；仅 ready + idle 时计时。

## 8. 动效

- 常规颜色/边框 transition 120–160ms。
- 轮询刷新、状态切换最多 180ms；没有整页淡入。
- 状态脉冲只用于正在生成/等待，不用在所有 badge 上循环。
- `prefers-reduced-motion: reduce` 下关闭脉冲、光标闪烁和位移动画。

## 9. 无障碍

- 所有交互元素可键盘到达，顺序与视觉顺序一致。
- 焦点样式至少 3px，和边框有足够分离。
- 触控目标 >= 44×44px；相邻操作间距 >= 8px。
- 队列使用 `aria-current`；状态变化区域使用克制的 `aria-live="polite"`。
- 倒计时每秒变化不得每秒钟被读屏播报；可将其设为视觉更新、分钟级播报。
- 对话更新使用 `role="log"` 或等价语义，不让整段历史反复播报。
- `textarea`、选择和参数均有可见 label；图标按钮有 `aria-label`。
- 颜色不是唯一状态信号；错误码、文字和图标同时存在。

## 10. 反模式清单

以下实现视为视觉验收失败：

- 恢复为创建表单占据首屏的纵向页面。
- 三栏里每一栏又塞入多张浮卡，形成“卡片套卡片”。
- 使用 9–11px 的功能性文字。
- 用绿色“已回收”表示仅仅提交了 stop 请求。
- 使用深色终端背景并与 ModelForge 现有浅色导航冲突。
- 用大面积渐变、发光或微动效掩盖信息层级问题。
- 把生命周期事实藏在原始 JSON 中而没有用户可读摘要。
- 让移动端依赖横向滚动表格。
- 使用生成图片充当产品截图或真实界面证据。

## 11. 视觉验收样本

设计与浏览器验收至少对照以下现有原型：

- `../trial-workbench.html?scenario=ready`
- `../trial-workbench.html?scenario=waiting`
- `../trial-workbench.html?scenario=streaming`
- `../trial-workbench.html?scenario=blocked`
- `../trial-workbench.html?scenario=stopping`
- `../trial-workbench.html?scenario=stopped`
- `../trial-workbench.html?scenario=create`

生产实现应保持结构、层级、可读性与状态语义，不机械复制 HTML 或原型脚本。
