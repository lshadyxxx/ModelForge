# Serving F1.1 决策与风险

Status: planning-only  
Review date: 2026-11-04

## 1. 已确定决策

| 编号 | 决策 | 理由 | 被放弃的方案 |
|---|---|---|---|
| D-01 | F1 合并版作为唯一生产主路径 | 延续现有品牌，信息架构最适合“选 Trial→验收→结束” | 同时维护 F1/F2/F3 三套生产页面 |
| D-02 | F2 只作为未来验收子视图 | 人工评级和后端持久化未定义，贸然上线会制造虚假能力 | P0 做完整实验平台 |
| D-03 | F3 只作为管理员高级运行检查器 | 生命周期透明度有价值，但整站深色、事件流和权限成本超出 P0 | 整站切换深色驾驶舱 |
| D-04 | 创建改弹层，基础/高级字段渐进披露 | 首屏当前被 11 个表单控件占据；字段仍有真实业务用途 | 删除高级字段或保持全展开 |
| D-05 | Trial 使用 `location.search + #serving` 深链 | 与 Training 已验证的 query 路由方式一致，不引入 router | 新增 React Router |
| D-06 | 原始状态统一派生为用户可执行状态 | 用户不应拼接 lifecycle/request/stop 三套枚举 | 三个状态并排展示 |
| D-07 | 生命周期回执使用现有表事实，P0 不加 migration | 0009/0011 已保存 process/instance/cleanup/lease/event 事实 | 新建回执表或改 Worker |
| D-08 | 真实实例的绿色回收成功只在 process 非 unknown + cleanup confirmed + instance deleted + lease released 时出现；未创建实例使用独立可核实状态 | 停止请求、进程退出、实例删除、租约释放是不同事实 | 点击结束即显示“回收成功”，或用同一个绿色态混淆“未创建实例”和“实例已删除” |
| D-09 | 会话只保存在当前页面 | 保持现有产品边界，避免隐式引入聊天持久化 | P0 持久化历史 |
| D-10 | 不新增 UI 框架、router、query、状态管理库 | 当前项目只有 React + TS + Vite，新增依赖会扩大审查面 | 引入 Ant Design、shadcn 等 |
| D-11 | 移动端使用抽屉承载队列和运行事实 | 保持会话主任务，避免 390px 横向表格与深滚动 | 缩小三栏或横向滚动 |
| D-12 | 保留 `features/serving/Serving` 的 App import | 降低跨模块装配风险，不改全局路由 | 新建独立路由页面并改 App |
| D-13 | 不自动购买、创建或预留云实例 | 现有 `ManualInstanceDialog` 明确要求用户手动创建 | 在 Serving 中调用优云创建接口 |
| D-14 | Worker 状态机和写路径保持不动 | 本次是 UI/UX 重构；回执只读投影即可满足展示 | 为界面改生命周期 |
| D-15 | P0 队列上限继续使用后端 200 条 | 当前列表接口即此上限，不加分页协议 | 为 UI 新增服务端分页 |

## 2. 关键假设

1. ModelForge 首版仍是本机单用户、无登录控制面。
2. 用户可以在优云控制台手动创建实例，并及时回到平台绑定。
3. 列表接口最多返回 200 条，队列不依赖无限滚动。
4. Trial ID 由后端生成 UUID；前端不把它们显示成业务名称。
5. `gpu_lease_events` 的 `instance_stopped`、`deletion_confirmed`、`process_exited` 是平台可观察事实，而不是云厂商强一致证明。
6. 现有浅色 ModelForge 品牌继续保留，未提供新版品牌规范。
7. runtime baseline 和 Adapter 兼容判断继续由现有后端/前端模块提供。
8. 用户接受“刷新页面会清空当前会话”，但必须被清楚提示。
9. 真实 GPU 验收需要用户另行提供环境；规划阶段不会自动触发。
10. 浏览器验收必须满足 AGENTS.md 的桌面焦点隔离要求。

## 3. 风险清单

### R-01 停止与真实回收被混淆

**严重度：高**  
**触发**：`stop_requested=true` 被前端直接渲染为成功，或轮询返回 `state=stopped` 就显示绿色。  
**影响**：用户以为实例已删除，实际仍计费或占用 GPU。  
**缓解**：

- 使用 lifecycle 分层回执。
- 完整成功条件集中在 `isCleanupComplete`。
- 所有成功文案经过 `serving-model` 测试。
- 不完整时显示“已结束，回收事实待核对”。  
**验证**：stopped+缺 lifecycle、deleted+held、failed cleanup 三组 UI 测试。

### R-02 生命周期投影泄露内部字段

**严重度：高**  
**触发**：直接返回整个 `gpu_reservations` row 或 `events`。  
**影响**：暴露 owner、generation、provider instance ID、region 或内部操作 ID。  
**缓解**：

- 白名单投影字段。
- 不返回 token、create operation、owner。
- 后端测试断言禁止字段不存在。  
**验证**：API key-set 合同测试。

### R-03 `state=stopped` 但事实不完整

**严重度：高**  
**触发**：Worker 已把 Trial 标 stopped，但 instance delete 或 lease release 尚未被记录。  
**影响**：错误显示回收成功，影响后续 GPU 创建。  
**缓解**：独立 `ended.incomplete`；保留刷新；提示 `gpu_busy` 风险。  
**验证**：浏览器与状态模型负向测试。

### R-04 只读投影依赖跨模块事实

**严重度：中**  
**触发**：serving 直接查 resources 表或复制租约规则。  
**影响**：长期出现两套事实、难以维护。  
**缓解**：只通过 `GpuLeases.get` 公开契约读取；serving 只做白名单投影。  
**验证**：代码审查和依赖方向检查。

### R-05 SSE 与停止生成竞态

**严重度：高**  
**触发**：旧流 delta 落到新 Trial；cancel 后立即本地 idle；页面切 Trial 时旧请求仍写消息。  
**影响**：显示错误输出、重复请求或错误允许发送。  
**缓解**：generation id、单 AbortController、切换时 abort、stop 后等待 done/详情确认。  
**验证**：多 chunk、旧流迟到、cancel、unknown 的纯函数和隔离服务测试。

### R-06 结束试用时有活动生成

**严重度：高**  
**触发**：用户点结束但当前 SSE 还在输出。  
**影响**：用户误以为可保存完整结果；或实例删除与生成取消并发。  
**缓解**：确认弹层明确提示“将停止当前生成”；结束流程继续依赖 Worker 现有顺序；UI 不直接释放租约。  
**验证**：streaming→stop trial 的隔离服务流程。

### R-07 非法或失效深链

**严重度：中**  
**触发**：`?trial=` 指向已删除/非法 UUID。  
**影响**：页面空白、错误地自动选择别的 Trial。  
**缓解**：保留 URL，显示 invalid_route 和回队列按钮；不自动改写。  
**验证**：invalid ID 与 404 浏览器测试。

### R-08 刷新清空会话被当成数据丢失

**严重度：中**  
**触发**：用户刷新后看不到之前的对话。  
**影响**：误以为是产品故障或认为历史已保存。  
**缓解**：在输入区与会话空状态显示“仅保存在当前页面”；刷新后提供明确的空会话说明。  
**验证**：刷新/切换 Trial UI 流程。

### R-09 200 条队列导致渲染和排序抖动

**严重度：中**  
**触发**：每 3 秒刷新 200 条并在前端重排、抢焦点。  
**影响**：滚动跳动、当前项丢失、输入被打断。  
**缓解**：当前项固定、稳定 key、纯函数排序、列表失败保留旧数据、过滤本地化；必要时虚拟化另行评审，不在 P1 自动添加。  
**验证**：200 条样本和 focus 记录。

### R-10 轮询导致状态闪烁

**严重度：中**  
**触发**：详情刷新先清空 detail，或列表失败导致骨架替代已有内容。  
**影响**：体验不安定，用户无法读取长文本。  
**缓解**：刷新保留旧数据，单独 `refreshing/stale`；不可覆盖正在编辑的输入。  
**验证**：列表失败、详情失败、慢响应。

### R-11 移动端操作路径仍过深

**严重度：中**  
**触发**：队列和运行事实都堆叠在会话下方。  
**影响**：390px 下用户看不到结束入口或切换 Trial。  
**缓解**：队列和运行事实均为可独立打开的抽屉，顶部可见入口，输入区固定。  
**验证**：390×844 的打开/关闭/焦点/安全区。

### R-12 全局 CSS 冲突

**严重度：中**  
**触发**：feature 使用 `.panel`、`.notice`、`.badge` 等全局类并修改共享选择器。  
**影响**：Training/Overview 等页面视觉回退。  
**缓解**：`serving-*` 命名空间、局部 CSS variables、CSS 只 import 到 serving feature。  
**验证**：浏览器检查 Training/Overview 和 `git diff -- app.css controls.css`。

### R-13 旧 Serving 回退路径被过早删除

**严重度：中**  
**触发**：P0 中途删旧组件或样式，后续发现主流程缺功能。  
**影响**：无法交付可回退状态。  
**缓解**：直到 P1-03 等价验收前保留旧实现和不被引用的部分；清理前做全仓引用检查。  
**验证**：rg 引用、回滚方案。

### R-14 手动实例绑定错误对象

**严重度：高**  
**触发**：用户把训练正在使用的实例绑定到 Trial，或输入了错误实例 ID。  
**影响**：平台后续停止/删除错误资源，训练失败或误清理。  
**缓解**：绑定面板重复“独立于训练”，展示快照要求，要求授权勾选；服务端冲突错误必须保留。  
**验证**：错误 ID、未勾选、`trial_not_waiting`、实例冲突负向测试。

### R-15 真实 GPU 验收缺口

**严重度：高**  
**触发**：无 GPU、无云账号、无可用 runtime。  
**影响**：只能证明 UI/合同，不能证明真实 Adapter 推理和回收。  
**缓解**：`NOT_RUN · G1` 独立保留；在最终报告列出环境缺口，不阻塞代码评审但阻止“真实业务通过”表述。  
**验证**：最终验收门。

### R-16 无新迁移导致部分时间事实不可得

**严重度：中**  
**触发**：`stop_requested` 只有布尔值，没有请求时间。  
**影响**：无法精确展示“何时提交停止请求”。  
**缓解**：只显示“已提交”，时间取现有事件；不伪造时间。若后续需要审计级时间线，另立 migration。  
**验证**：回执字段审计。

### R-17 事件数量与隐私

**严重度：中**  
**触发**：每个 Worker 循环都可能记录 `renewed`，或事件包含内部动作。  
**影响**：响应体膨胀、泄露内部节奏。  
**缓解**：过滤 `renewed`、最多 50 条、只暴露白名单动作和时间。  
**验证**：事件合同测试。

### R-18 API 投影服务不可读

**严重度：中**  
**触发**：`lease_id` 存在但资源记录缺失或查询失败。  
**影响**：前端无法给出成功回执。  
**缓解**：HTTP 200 + `lifecycle.status=unavailable`，保留 Trial 基本信息，显示待核对。  
**验证**：故障注入测试。

### R-19 基座地域与实例选择冲突

**严重度：中**  
**触发**：外部只读基座固定地域，用户选择了另一地域。  
**影响**：创建失败，用户无法理解原因。  
**缓解**：表单展示基座地域；服务端 `base_region_mismatch` 映射为用户可操作错误。  
**验证**：创建负向测试。

### R-20 运行时或 Adapter probe 未通过

**严重度：中**  
**触发**：实例镜像未装兼容 runtime，或者 Adapter 指纹不一致。  
**影响**：准备失败，可能误当成 ready。  
**缓解**：显示准备步骤与 `gpu_runtime_incompatible` / `adapter_probe_pending`；不自动删除实例。  
**验证**：blocked/preparing 状态截图。

### R-21 浏览器隔离边界造成验收缺口

**严重度：中**  
**触发**：浏览器驱动无法证明不激活系统窗口/焦点。  
**影响**：无法执行完整点击验收。  
**缓解**：按 AGENTS.md 停止该步骤，使用 HTTP/自动化/隔离服务证据，并明确 `BLOCKED · U1`。  
**验证**：验收报告中的工具与隔离说明。

### R-22 P2 评级被误读为已持久化

**严重度：中**  
**触发**：F2 子视图前端保存“有用/偏题/不安全”，用户以为形成正式验收记录。  
**影响**：数据可信度受损。  
**缓解**：P2 单独批准；若只存在页面内，必须明确标注“本页标记，不作为验收事实”。  
**验证**：P2 单独规格。

## 4. 回滚与降级

- P0-01/02/03/04/06 均以 feature 文件为主，可按票据范围回滚，不触碰数据库。
- P0-05 是只增字段；前端可忽略。若回执查询不稳定，可关闭回执 UI，但保留 Trial 原有详情。
- 不通过回滚 migration 解决 UI 问题；本次不新增 migration。
- 结束/回收遇到事实不完整时，UI 降级为待核对，不提供“强制释放”。
- 浏览器自动验收不可用时，降级为 HTTP + 隔离服务 + 手工可审查证据，并保留缺口。
- 在 P1-03 等价验收完成前，不删除旧 Serving 实现作为最终保底。

## 5. 停止条件

出现以下情况必须停止当前票据：

1. 为显示回执需要新表/新字段。
2. 需要改 Worker 的停止、进程退出、实例删除或租约释放顺序。
3. 现有 API 事实不足以区分 process/instance/cleanup/lease。
4. 需要改 `InstanceFields` 的字段或删除业务配置。
5. 需要新增全局依赖、组件库或路由库。
6. 浏览器验收无法证明隔离且影响关键路径。
7. 发现当前分支有用户未提交改动与票白名单重叠，无法安全区分。
8. 需要越过 ModelForge 目录或修改其他 worktree。

## 6. 非阻断待确认项

这些问题不改变当前设计方向，可在实现前或评审时再决定：

- 队列分组最终使用“需处理/进行中/已结束”还是更细状态组。
- 固定验收问题是否需要产品团队替换为正式业务题库。
- P2-01 人工评级是否持久化，若持久化需另立数据合同。
- P2-02 管理员视图是否需要独立权限模型。
- 最终浏览器证据工具是否能在当前宿主满足隔离要求。

## 7. 决策复核

若后续证据出现以下变化，应重新评审：

- 列表接口增加分页或后台筛选。
- GPU 租约事件无法稳定反映实例删除或租约释放。
- 真实 GPU 验证证明停止/清理顺序需要新的中间状态。
- 产品要求会话持久化或多人共享。
- 品牌系统升级为深色或新 token。
