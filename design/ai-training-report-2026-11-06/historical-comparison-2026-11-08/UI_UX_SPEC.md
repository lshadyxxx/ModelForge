# ModelForge AI 训练诊断
## 历史对比 UI/UX 规范

日期：2026-11-08
状态：本地实现完成，桌面与移动端验收通过
视觉基线：方案 A v2「专业诊断信号台」
范围：训练详情页 AI 诊断入口、报告历史对比区块、基线与证据交互

## 1. 设计目标

用户打开一次训练报告后，应能快速回答：

1. 有没有可比的历史运行？
2. 两次运行到底改了什么？
3. 本次训练信号比上次好还是差？
4. 这个结论有多可信？
5. 哪些是真实模型效果，哪些只是训练代理信号？
6. 下一步应该只改哪个变量？

界面必须保持 ModelForge 的专业、紧凑和证据优先，不将历史对比做成营销式“提升百分比”。

## 2. 信息架构

AI 诊断页签：

```text
AI 诊断
├─ 页面标题与报告操作
├─ 历史基线选择
├─ 历史对比结论
│  ├─ 训练信号
│  ├─ 置信度
│  ├─ 交付信号
│  └─ 模型效果未验证
├─ 参数变化
├─ 指标对比
├─ 混杂因素与限制
├─ 当前双 Gate 结论
├─ 关键发现
├─ 下一步实验
└─ 双证据台账
```

对比模块位于“报告摘要”和“当前运行双门禁”之间。用户应先知道“和谁比、能不能比、结果方向”，
再进入当前单运行的细节。

## 3. 运行总览入口卡

### 3.1 已有报告

在现有 AI 入口卡增加一行对比摘要：

```text
较基线：训练信号改善 · 中等置信度
模型效果：未验证
```

如果 `no_baseline`：

```text
未找到同一基座与数据集的成功历史运行
```

如果 `not_comparable`：

```text
历史运行存在，但数据切分或基座不一致
```

### 3.2 生成中

```text
正在对比历史训练并生成可审计报告
```

显示当前 subject attempt ID；若 baseline 已解析，显示 baseline attempt ID。

## 4. 基线选择器

### 4.1 位置

报告页顶部，标题下方，与生成/重新生成按钮同一区域。

### 4.2 选项

```text
对比基线
[ 自动：最近一次成功运行 ▼ ]
```

展开后：

- `自动：最近一次成功运行`
- 每个候选：
  - Task 名称
  - Attempt #编号
  - 日期
  - `strict / conditional`
  - Best Eval Loss 或“未上报”
  - 参数变化数
  - 混杂因素数量
- `不对比历史`

首版不做搜索框；候选最多 20 条，按时间倒序。

### 4.3 候选状态

| 状态 | 展示 |
|---|---|
| 可严格比较 | 绿色描边，`严格可比` |
| 条件可比 | 琥珀色，`有混杂因素` |
| 无指标 | 灰色，`指标不足` |
| 当前 Attempt | 不出现在列表 |
| 非成功 | 不出现在首版候选 |

### 4.4 交互规则

- 选择候选不会自动调用模型。
- 已有报告时，切换基线后按钮文案变为 `用新基线重新生成`。
- 无报告时，基线随“生成 AI 诊断”一起提交。
- 如果用户只切换候选但未生成，旧报告仍显示自己的 frozen baseline，并用提示条说明选择未应用。

### 4.5 禁用

- AI 功能关闭：选择器只读。
- 当前 Attempt 非终态：不可生成。
- 当前 Attempt 为 `failed/cancelled`：隐藏历史基线选择，显示
  `失败复盘不做训练效果对比`；仍可生成单运行有限复盘。
- 候选接口失败：选择器显示错误和重试，不影响“不对比历史”模式。

## 5. 历史对比主卡

### 5.1 顶部标题

```text
HISTORICAL COMPARISON
这次训练比上次更好吗？
```

副标题：

```text
只比较训练信号与交付信号；没有同评测集分数时，不判断真实模型效果。
```

### 5.2 基线摘要

```text
当前 Attempt #23
基线 Attempt #19 · 2026-11-07 18:42 · succeeded
同一基座 · 同一数据集 · 同一 split
```

长 ID 使用可复制短 ID。

### 5.3 四个状态块

| 块 | 内容 |
|---|---|
| 训练信号 | improved / worsened / mixed / flat / inconclusive |
| 置信度 | high / medium / low / none |
| 交付信号 | improved / worsened / same / inconclusive |
| 模型效果 | 首版固定 `未验证` |

`训练信号` 使用最大视觉权重，但不能使用庆祝式绿色大面积渐变。

### 5.4 训练信号文案

| 状态 | 文案 |
|---|---|
| improved | 训练信号较基线改善 |
| worsened | 训练信号较基线恶化 |
| mixed | 训练信号与健康信号方向冲突 |
| flat | 训练信号基本持平 |
| inconclusive | 训练信号无法判断 |

置信度：

```text
中等置信度 · Best Eval Loss 变化超过 2% 阈值
```

低置信度：

```text
低置信度 · 双方仅 1 个 Eval 采样点
```

### 5.5 模型效果

固定显示：

```text
模型效果：未验证
原因：两次 Adapter 都没有同一独立评测集上的可比较分数。
```

不得用绿色成功态。建议使用中性或浅琥珀色“未验证”标签。

## 6. 参数变化

### 6.1 表头

```text
参数变化 · 3 项
```

### 6.2 表格

| 参数 | 基线 | 当前 | 类型 |
|---|---:|---:|---|
| learning_rate | 2e-4 | 1e-4 | 优化参数 |
| lora_rank | 8 | 16 | 优化参数 |
| seed | 42 | 43 | 随机性 |

同时展示：

```text
多参数共同变化，不能把结果归因给单个参数。
```

### 6.3 无变化

```text
训练参数没有变化。本次对比更接近重复运行，差异可能来自随机性或运行环境。
```

### 6.4 输入/环境变化

参数表下方显示独立警告：

```text
输入处理变化：template qwen3_nothink → qwen
运行环境变化：runtime lock 不一致
硬件变化：NVIDIA RTX 4090 → NVIDIA A10
```

## 7. 指标对比

### 7.1 主指标

```text
Best Adapter Eval Loss
基线 0.xxxx → 当前 0.xxxx
绝对差 ... · 相对差 ...
```

每个数字旁有 `evidence` chip，可跳到 `E-BASE-METRICS` 或 `E-METRICS`。

### 7.2 副指标

- Final Eval Loss
- 最低/最新 Eval Loss
- Eval 采样点
- Token 溢出数量
- Runtime mismatch
- 交付状态

### 7.3 缺失

```text
基线未上报 Final Eval Loss
```

不得显示 `0`、`—%` 或“无变化”。

### 7.4 禁止图表

如果两次运行 step/epoch 不可对齐，首版不绘制叠线图，不制造同一训练预算的视觉暗示。

可显示“各自运行曲线”作为 Phase 2，不在首版抢占主结论空间。

## 8. 混杂因素与限制

列表样式：

```text
[混杂] Runtime lock 不一致
[覆盖] 双方只有 1 个 Eval 采样点
[归因] 同时修改 2 个训练参数
[随机] Seed 发生变化
```

卡片底部：

```text
这些因素降低归因强度，但不阻止展示已经观测到的训练信号。
```

## 9. 当前运行双门禁

历史对比卡之后仍显示当前运行自己的：

- 训练健康度；
- 可交付性；
- Gate reason codes；
- evidence chips。

历史对比不能覆盖当前 Gate。

视觉上用细分隔线和 `CURRENT RUN` 标签区分。

## 10. 关键发现

现有 FindingLedger 增加 comparison category：

```text
comparison
```

严重度沿用 `blocked / attention / passed / info`，但对比类发现默认 `info` 或
`attention`，不能用 `passed` 表示“新模型更好”。

筛选器增加：

- 全部；
- 对比；
- 需关注；
- 阻断；
- 通过；
- 信息。

## 11. 下一步实验

实验卡必须包含：

- 假设；
- 单一变化参数；
- 保持不变的字段；
- 前置条件；
- 置信度；
- `应用为未提交草稿`。

示例：

```text
P1 · 验证 learning_rate
保持 lora_rank、epochs、seed 和 template 不变，仅保留 learning_rate 变化，重复一次训练。
```

没有可比基线时，实验建议只能来自当前运行诊断，不能写“继续优化上次”。

## 12. 证据台账

在现有 EvidenceInspector 上增加：

- `当前运行` / `历史基线` / `对比结果` 三组；
- 双证据跳转；
- baseline 证据使用 `E-BASE-*` 标签；
- 显示 source locator、字段路径、coverage、digest 和 unavailable reason；
- comparison 证据显示 policy version。

对比 Claim 必须同时有 subject 和 baseline 证据入口。

## 13. 状态设计

### 13.1 加载候选

```text
正在查找同一基座与数据集的历史运行…
```

Skeleton 不超过一张卡片，不阻塞当前运行信息。

### 13.2 无候选

```text
未找到可比历史
当前基座、数据集和 split 还没有另一次成功运行。
仍可生成单次运行 AI 诊断。
```

按钮：

- `生成当前运行诊断`
- `重新查找历史`

### 13.3 不可比

```text
历史运行不可比
数据切分哈希不同，验证集并非同一批样本。
```

### 13.4 对比生成中

```text
已冻结当前运行和历史基线
正在计算比较结果并通过模型解释…
```

必须显示两个 Attempt 短 ID。

### 13.5 对比证据不足

```text
历史基线指标不足
Best/Final Adapter 没有可读 Eval Loss，因此不能比较训练信号。
```

报告仍可显示当前运行 Gate。

### 13.6 报告 stale

```text
历史对比依据已过期
当前运行或基线来源发生变化。该报告保留为历史版本。
```

不自动重新生成。

### 13.7 模型效果未验证

这是正常状态，不是错误。不得使用红色错误条。

```text
├────────────────────────────────────────────────────────┤
│ 当前运行双门禁                                         │
├────────────────────────────────────────────────────────┤
│ 关键发现                                               │
└────────────────────────────────────────────────────────┘
```

主内容最大宽度沿用训练工作台，不新增全屏 dashboard。

## 15. 移动端 390

布局：

- 状态块 2×2；
- 参数表和指标表改为 label/value 卡或可横向滚动表格；
- 页面不能出现横向溢出；
- baseline 选择器使用原生 select 或可访问的 dialog；
- 操作按钮换行，不压缩到无法点击；
- 吸顶章节导航保留；
- 证据 jump 后滚动位置正确。

## 16. 操作

### 16.1 生成

- 未生成报告：`生成 AI 诊断`。
- 生成中：禁用并显示 progress。
- 终态前：只显示说明，不显示可点击生成。

### 16.2 重新生成

- 有报告时显示 `重新生成`。
- 若 baseline 选择已变更，显示 `用新基线重新生成`。
- 生成中不覆盖当前报告。

### 16.3 复制摘要

复制内容包含：

- 当前 Attempt；
- 基线 Attempt；
- 可比性；
- 训练信号与置信度；
- 模型效果未验证；
- 关键参数变化；
- 证据 digest 前 12 位。

### 16.4 应用建议

- 只生成未提交草稿；
- 必须显示 base subject config 和 patch；
- 不允许从 baseline 误写到 subject；
- 确认文案：

```text
这里只生成未提交配置草稿，不会创建 GPU 或提交训练。
```

## 17. 可访问性

- 状态标签不能只靠颜色；
- 表格必须有 caption 或 aria-label；
- 对比状态块使用可读文本；
- evidence chip 是真实链接，支持键盘；
- 对话框 focus trap；
- 390 下触控目标 ≥ 40px；
- 对比方向使用“降低/升高/持平”，不只使用箭头；
- `prefers-reduced-motion` 下不播放 spinner 之外动画。

## 18. 视觉语言

- 奶油底、深蓝标题、蓝色主操作、琥珀 warning、红色仅用于阻断/错误；
- 不使用大面积紫色 AI 渐变；
- 不把“AI”变成魔法图标主导；
- 对比卡使用细边框、轻底色和信息密度；
- “模型效果未验证”保持中性；
- 参数 diff 使用 code 风格；
- 证据 chip 与现有 A v2 一致。

## 19. 验收交互清单

必须验证：

1. 自动基线候选显示和选择；
2. 显式基线切换；
3. `不对比历史` 模式；
4. 无候选空状态；
5. 不可比状态；
6. 生成中状态；
7. 成功报告；
8. 低置信度报告；
9. 多参数变化提示；
10. 展开 baseline evidence；
11. 展开 subject evidence；
12. 复制摘要；
13. 应用建议草稿；
14. 重新生成；
15. Attempt 切换后旧报告不串数据；
16. 1440 与 390 无横向溢出；
17. Console error = 0；
18. window error / unhandled rejection = 0。
