# Ticket 02 数据集生命周期实施记录

日期：2026-10-29。范围：`<internal-evidence>`。本记录只覆盖 messages JSONL 数据集版本、MinIO 正式对象、PostgreSQL 元数据、确定性验证集拆分、发布与删除保护；不包含模型导入、训练或优云实例。

## 已落地

- 服务端接受 UTF-8 messages JSONL，支持 system/user/assistant 的单轮和多轮文本对话。
- 校验按原文件物理行号报告字段路径与原因；无效版本进入 `invalid`，不能发布。
- 数据集原始文件进入 MinIO，PostgreSQL 保存数据集、版本、状态、大小、SHA-256、预览和校验错误。
- 默认按 10%、seed 42 生成确定性训练/验证拆分；重复内容不会跨集合，若重复组大小无法精确达到目标则选择最接近的可行组合。实际 split manifest 及 SHA-256 写入 MinIO/数据库，重复请求复用同一结果；请求比例最多支持 6 位小数。
- 发布只允许有效 draft；有引用的版本返回 409 并列出引用类型/标识；对象确认删除后才删除数据库记录。
- 上传或 split 的存储/数据库故障会返回可重试的对象身份和 `cleanup_required` 标记；失败路径测试覆盖回读损坏、数据库更新失败和清理失败。
- 容量初始值由后端配置提供：100 MiB 文件、100000 个有效样本、1 MiB 物理行、最多 100 个校验错误、20 个预览样本。
- `GET /api/v1/datasets/limits` 暴露配置限制、配置版本和 `locked` 状态；当前为 `initial-2026-10-29`、未锁定，待真实传输/校验测量后再锁定。

验收脚本实际覆盖：

1. 通过 API 创建有效版本，直接查询 PostgreSQL 核对 `draft`、样本数和摘要。
2. 通过容器内 MinIO 客户端回读原始对象，核对大小和 SHA-256。
3. 生成并回读 split manifest，核对 10% 拆分、对象摘要和重复请求的摘要稳定性；单元测试覆盖重复组大小超过目标时的最近可行拆分和比例精度拒绝。
4. 发布版本，从 API 下载原始字节并核对响应 checksum。
5. 上传包含缺少 assistant、非法 role 和非法 JSON 的文件，确认 422、物理行错误和 `invalid` 状态。
6. 确认无效版本可清理；人为登记引用后删除返回 409，移除引用后对象和元数据均可清理，删除后查询返回 404。

脚本输出的版本和对象均在 `finally` 中清理；本次验收没有留下正式数据集对象或版本记录。Compose 依赖仍按项目当前运行状态保留，未关闭其他项目服务。
