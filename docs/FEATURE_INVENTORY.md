## ModelForge：首版逐动作清单

## 旧版原型缺口与本次改版依据

以下是旧版 [prototype.js](../designs/modelforge-mvp/prototype.js) 的审阅记录，保留为改版依据。新版入口与实际检查范围见[原型说明](../designs/modelforge-mvp/README.md)和[检查记录](../designs/modelforge-mvp/review/verification-2026-10-29.md)。

| 当前缺口 | 对用户的影响 | 下一轮建议 |
|---|---|---|
| `renderTraining()` 将新建表单和一条成功任务的详情放在同页。 | 用户容易混淆“还没提交的参数”与“已经完成的结果”。 | 分成任务列表、新建向导、任务详情。详情顶部固定任务/Attempt 身份；新建向导按模型与数据 → 计算环境 → 参数 → 提交摘要推进。 |
| 计算环境将 GPU 与示例镜像放在同一表格，只提供单个示例选择按钮。 | 区域、GPU、CPU/内存、镜像、库存与报价之间的关系没有真正被表达。 | 做联动资源选择器，保留已选摘要；显示库存/报价时间和失效反馈，冲突就近说明。 |
| 四种模型来源共用一块导入区，来源、平台资产、一次导入作业的层次较弱。 | 公共目录“引用”与上传/下载“复制文件”容易混淆。 | 模型库保留明确来源筛选；导入流程按来源展开；导入作业单列进度与恢复操作；详情解释外部引用或托管状态。 |
| 原型依赖全局“演示状态”下拉制造故障。 | 能展示失败文案，尚不能说明用户从实际动作如何到达失败、如何恢复。 | 保留演示标记，同时围绕动作设计失败路径：发布前校验、提交时缺货、回传失败、试用清理失败。用实体详情承接恢复。 |
| 任务阶段、Loss、产物和清理状态集中在长页。 | 用户难以判断当前最重要的状态和下一步按钮。 | 顶部给出当前阶段与主动作；详情分概览、指标、日志、产物、计算实例；优先展示阻塞原因。 |
| 推理页的启动配置与聊天并列，但“开通中”信息不足。 | 冷启动等待时容易重复点启动或误认为卡住。 | 显式区分未启动、申请中、准备/加载中、就绪、结束中和清理失败；显示阶段、已用时及可执行动作。 |

这些是待比较的交互建议，用户尚未认可新的布局或视觉方向。六模块沿用已确认范围；增加的列表/详情/向导属于把既有动作组织成页面，并不自动增加租卡、评测或多人管理功能。本次已将“创建训练 → 监控 → 选择产物 → 启动试用 → 对话 → 回收”做成连续可点击流程；六入口保留，错误恢复放入对应任务或实例上下文。全站风格及具体布局仍需用户审阅。
