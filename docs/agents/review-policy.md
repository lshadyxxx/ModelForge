# ModelForge 审查与验收策略

## 审查入口

`code-review` 与 `jury` 先读取 `docs/agents/cross-model.json`；
读取领域文档的规则见 `docs/agents/domain.md`。
问题和规格的读取、依赖及关闭规则见 `docs/agents/issue-tracker.md`。

## 审查范围

有提交历史时，审查前固定本地基准 SHA，记录完整变更，
包含暂存、未暂存及未跟踪文件。没有远程时使用本地引用。
尚无首次提交时按完整文件审查，并注明没有提交基准；
不使用不存在的 `HEAD` 或 `origin/main`。

保留三个独立审查轴：

- Standards：是否遵守根 Agent 入口、已确定架构及项目约定。
- Spec：是否满足本地规格、任务范围和验收条件。
- Adversarial：失败、取消、重试、重启和部分成功时如何表现。

host-only 使用当前宿主的原生审查者；原生能力不足时排队或报告覆盖不完整。
不启动外部 Claude、Codex、Cursor Agent 或 OMP CLI，
不声称完成跨模型家族验证。

## ModelForge 审查重点

按变更涉及的范围检查：

- API 与 Worker 的进程边界，以及共享后端业务规则。
- PostgreSQL 任务领取、状态转换、心跳和 GPU 资源租约。
- Task 与 Attempt 的区分、重试隔离、不可变输入和产物血缘。
- MinIO 上传及校验完成后才标记产物可用；缓存可重建。
- 训练退出、产物可用、服务 ready 和资源释放分别验证。
- 取消及停止后的子进程回收，训练与推理的单 GPU 互斥。
- 浏览器同源 API/SSE 路径及服务端凭据边界。

## 证据与完成条件

每项发现记录严重度、文件行号、实际影响和证据；
证据不足时保留待验证状态。缺失的审查轴明确标为未完成。
沿用所调用审查技能的判定规则，报告各轴结果。

按改动运行相关检查；首次实现时将真实命令记录在对应规格或开发文档，
当前不编造尚不存在的构建或测试命令。

区分文档检查、自动化测试、模拟执行器验证、真实服务验证和 GPU 验证。
健康检查通过不能替代对象存储读写校验、任务闭环或真实模型验收。
未运行的项目注明原因；未满足验收条件的任务保持未关闭。

纯流程配置只检查配置结构、文档引用、改动范围和 Git 边界，
不启动应用、存储服务或 GPU 任务。
