# 技术栈决策

本页记录 ModelForge 的架构决策；本地基础骨架已实现，业务组件逐票实施；具体版本和验收状态见[运行文档](RUNNING.md)。

首版追加优云智算 API 驱动的远程训练、权重回传与推理试用，见 [ADR-0001](adr/0001-ucompshare-remote-execution.md)。下方本地运行图保留为参考，云端执行拓扑以 [ARCHITECTURE.md](ARCHITECTURE.md) 的远程执行边界为准。

## 应用结构

```text
React + Vite Web（静态单页应用）
    │ HTTP / SSE
    ▼
Nginx / Vite dev proxy ── FastAPI API ─── PostgreSQL（平台元数据、任务状态）
                                │
                                ├── MinIO（正式数据集、模型文件和训练产物）
                                └── PostgreSQL 任务表
                                      ▲
                                      │ claim / heartbeat / status
                              独立 Worker 进程
                                ├── 训练执行器（首期单 GPU）
                                └── 推理服务管理器 → vLLM 子进程

Worker / 推理运行时 ←→ MinIO（下载所需文件、上传需持久保留的产物）
        └── 本地临时工作目录与可重建缓存
```

## 组件选择

| 领域 | 建议 | 采用理由与边界 |
|---|---|---|
| 前端 | React、TypeScript、Vite | 管理型单页工作台；Vite 负责开发服务器和静态构建，生产由 Nginx 等静态服务器托管。 |
| 后端 API | Python、FastAPI、Pydantic | 与 Python 模型生态一致，提供类型化请求校验及 OpenAPI。 |
| 持久化 | PostgreSQL（已确定） | 统一任务、数据集、模型资产和服务的结构化元数据；不维护 SQLite 兼容后端。 |
| 后台任务 | PostgreSQL 任务表＋独立单 Worker | API 和 Worker 分进程运行；先实现原子领取、租约、心跳、取消和恢复，并发扩展后再评估 Redis/RQ、Celery 或其他队列。 |
| 训练 | 文本 SFT＋LoRA；已验收基线为 LLaMA-Factory 0.9.5 | 训练方式已确认，输入为 messages JSONL；训练逻辑和平台状态机解耦。Qwen3-0.6B＋RTX 4090 基线已通过真实训练，其他模型/镜像组合由票据 06 验证。 |
| 推理 | vLLM 0.32.0 子进程适配器 | API 服务和模型服务生命周期隔离，已通过独立实例真实 Adapter 加载、健康检查、SSE 多轮对话、停止生成和服务回收；更广组合仍由票据 06 跟踪。 |
| 文件 | MinIO（已确定）＋外部只读基座引用 | MinIO 保存正式数据集、托管模型、Adapter 和训练产物；优云公共基座直接读取云端目录，PostgreSQL 保存来源和内容指纹。本地目录仅作临时工作区或缓存。 |
| 控制面运行 | Docker Compose | 本地开发提供 Web、API、Worker、PostgreSQL 与 MinIO；GPU 任务接入优云单实例，不引入 Kubernetes。 |

## 已确定决策

- Web 使用 React + Vite，不使用 Next.js；前端作为单页应用构建和托管。
- 浏览器只访问 Web 同源地址，由开发代理或 Nginx 将 `/api`、`/events` 转发到 FastAPI；MinIO 凭据只由后端持有。
- FastAPI API 和 Worker 使用同一 Python 代码库、不同进程入口；训练与推理子进程由 Worker 管理。
- 所有平台元数据、任务状态、租约、产物索引和推理服务记录统一使用 PostgreSQL。
- MinIO 从首期起保存正式数据集、用户上传/模型平台导入的模型和训练产物；优云公共基础模型的外部只读例外见 [ADR-0002](adr/0002-external-readonly-base-models.md)。本机绝对路径不作为正式资产标识，公共目录路径也不能替代内容指纹。
- 本地开发通过 Docker Compose 启动 PostgreSQL 与 MinIO；本地磁盘只用于暂存、运行工作区和可重建缓存。
- 首期单平台 Worker、单 GPU；纳入优云资源 API、远程执行及产物回传。Redis、Kubernetes、多机集群调度和其他云厂商适配后置。
- 首版个人本机访问，控制面仅绑定回环地址，不做登录与用户管理；云凭据仅由后端环境配置注入，云端推理端口不公开为无鉴权服务。
- 推理提供页面内多轮流式对话和停止当前生成；停止生成与结束试用/删除实例分开处理，不持久化对话历史。
- 失败/取消训练不发布部分 Adapter，确认远程训练停止后删除实例；训练成功但必需产物回传失败仍保留实例以恢复回传。

## 关键工程约束

- 每项任务保存不可变的输入快照，包括数据集版本、模型标识和归一化后的训练参数。
- 训练 Worker 与推理服务共享 GPU 时，必须经过同一个资源租约或调度边界。
- 运行子进程要持续收集日志、处理取消请求并在退出路径释放资源。
- PostgreSQL 保存托管文件的 bucket、object key、SHA-256、大小、来源及可用状态，也保存外部只读基座的文件清单和内容指纹；托管正式文件存放 MinIO，不以本机绝对路径作为资产标识。
- 训练与推理启动前，从 MinIO 下载并校验托管输入，或按外部只读引用核对优云公共基座；需要持久保留的输出上传并校验 MinIO 成功后，才将对应产物标记为 available。
- 本地缓存可重新下载；未完成上传的输出保留为待同步或失败状态，不因为 MinIO 不可用而静默改用本地正式存储。
- `.env`、云凭据、模型权重、用户数据、训练产物和缓存不进入 Git。

## 后续兼容与容量决策

- 当前已锁定基线是 Qwen3-0.6B、单卡 RTX 4090、Python 3.13.5、训练运行时与 vLLM 0.32.0 推理运行时；完整 Python/PyTorch/CUDA、模型模板和镜像矩阵仍由票据 06 跟踪。
- 数据集、上传、生成和模型容量上限仍需基于真实传输与显存测量校准；见[产品规格](../<internal-evidence>)和[功能清单](FEATURE_INVENTORY.md)。
- 优云远程任务通道、实例关联、停止/删除核实和租约释放已完成当前组合的真实闭环；更广供应商场景和生产部署不在当前 MVP 验收内。
- MinIO bucket 与 object key 规范、访问凭据、校验策略和清理保留规则。
- 模型目录上传按文件恢复已完成；ModelScope 大文件下载已支持持久分片和 HTTP `Range` 字节续传。目录上传的单个大文件分片协议仍后置，不因优云公共基座可直接读取而省略自有模型上传能力。
- 多人访问、登录与权限后置；扩大控制面访问范围前须先补充访问控制规格。

## MinIO 接入约定

- 平台对象按数据集版本、模型版本和训练 attempt 分配不可变的 object key，重试使用新的 attempt 输出前缀，避免覆盖历史产物。
- 首期文件上传由后端负责校验和写入 MinIO；浏览器不持有 MinIO 服务端访问密钥，是否采用短期签名直传在大文件优化阶段另行决定。
- 上传前先登记待处理元数据；所有必需文件上传并校验完成后，再提交产物清单和可用状态。上传失败保留错误和重试信息，不将半成品暴露为可部署模型。
- MinIO 健康检查之外，还需用临时对象验证写入、读取、内容校验和删除；失败时可诊断且不得误报文件存储可用。
- 删除或清理对象前检查数据集版本、任务和服务的引用，分别记录数据库状态和对象删除结果，清理失败可以重试。
