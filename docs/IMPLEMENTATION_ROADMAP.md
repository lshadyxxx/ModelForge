## 1. 本地管理骨架

- 初始化 React + TypeScript + Vite 前端、FastAPI API/Worker 两个进程入口、共用依赖装配和开发环境配置。
- 增加健康检查、应用设置和统一错误结构。
- 提供最小工作台导航、API 客户端和 Vite `/api` 开发代理。
- 用根目录 `compose.yaml` 启动前端、API、Worker、PostgreSQL 和 MinIO；将 PostgreSQL 与 MinIO 的容器数据目录分别绑定挂载到根目录 `docker-db/postgres/`、`docker-db/minio/`，API 与 Worker 共用后端代码和构建。
- 加入 PostgreSQL schema migration 与连接池配置；由 Compose 单次迁移任务执行迁移，迁移成功后才启动 API 和 Worker。
- 首版控制面只绑定本机回环地址，内部依赖不对局域网或公网开放；不实现登录与用户管理，云凭据只由后端环境配置注入。
- Web/API 的本机监听地址及 Compose 发布端口须限定 loopback；PostgreSQL、MinIO、Worker 探针默认不发布宿主机端口。
- 实现 MinIO 连接配置、开发 bucket 初始化和文件存储接口，保持访问密钥仅在服务端使用。

第一阶段详细实现规格与运行验收步骤见[可运行基础骨架规格](../<internal-evidence>)。

验收：新环境按文档启动后能打开工作台，静态前端通过同源路径连接 API，页面能如实展示 API、PostgreSQL、MinIO 和 Worker 状态；API 与 Worker 可独立启动和停止，迁移任务可重复执行且失败会阻止应用进程启动。重启 Compose 服务后 PostgreSQL 记录和 MinIO 对象仍保留；独立验证脚本通过 MinIO 上传、下载、内容校验、删除及 PostgreSQL 元数据核对。

## 2. 数据集登记与校验

- 首版接入 messages JSONL 文本对话；单轮和多轮样本提供页面示例，服务端按产品规格的容量限制方案校验并向页面展示。
- 训练输入从固定数据版本划分默认 10% 验证集，保存实际拆分清单及摘要；重试复用同一拆分，训练与验证样本保持独立。
- 实现上传、格式校验、版本标识、预览和删除保护。
- 将数据集版本文件直接保存到 MinIO，在 PostgreSQL 记录 bucket、object key、SHA-256、大小和校验报告。

验收：messages JSONL 单轮和多轮样本可上传、预览、发布；无效 JSON/消息记录按物理行号报错并拒绝发布。每个训练输入可以确定地指向已发布的数据集版本；清理可重建本地缓存后，仍能从 MinIO 下载并校验同一原始版本。

实施状态（更新至 2026-10-31）：数据集后端已提交并经新镜像回归；覆盖有效/无效 JSONL、MinIO 回读、PostgreSQL 元数据、确定性 10% split、发布、下载 checksum、引用保护和清理。容量限制仍是首版初始配置，训练/优云执行未开始。模型目录上传后端增量已通过真实存储验收；ModelScope 已支持默认/命名分支解析为固定 commit 后台导入，数据集/模型 UI 已接入；2026-10-31 新增优云只读目录接口和计算环境入口，真实账号目录筛选、分页和库存 API 已经同源 HTTP 验收，页面视觉/交互仍待安全隔离浏览器验收。Hugging Face 暂缓；外部引用登记与指纹内核已实现并经本地 fixture 验证，实际实例通道、训练和推理尚未实现，见[外部基座记录](implementation/external-bases-2026-10-31.md)。详见[数据集实施记录](implementation/datasets-2026-10-29.md)和[模型实施记录](implementation/models-2026-10-30.md)。

## 3. 训练任务与模拟执行器

- 实现任务状态机、任务输入快照、单 Worker 领取、取消和日志查询。
- 由 `resources` 模块统一管理单 GPU 租约；任务领取与训练状态仍归 `training`，Worker 入口只负责驱动。
- 先实现明确标识的 Fake Executor，用于无 GPU 环境验证任务生命周期、错误和 UI；使用不申请 GPU 的轻量测试进程单独验证真实子进程停止和退出。模拟验证不代表 GPU 计算或训练/推理硬件互斥已验证。
- 持久化退出码、错误阶段和产物清单。
- 用模拟文件覆盖 MinIO 上传失败、重试与产物可用状态，明确标记为模拟产物，不作为真实可部署模型。
- 通过 `models` 的最小产物登记能力管理上传、校验和可用性，训练模块不重复实现模型发布规则。

验收：提交、排队、运行、取消、失败和成功路径均可重复测试，重启后状态可解释。

## 4. 接入真实训练

- 首版实现文本 SFT＋LoRA；QLoRA、DPO、全参数训练和多模态训练后置。
- 实现模型、GPU 与镜像的真实目录查询、界面选择和兼容性检查；不硬编码特定模型或显存。训练框架、CUDA/PyTorch 等版本在实施阶段验证，真实验收记录从页面选定的实际硬件和环境。
- 接入优云配置/库存、镜像与公共模型目录；用户选择单 GPU 规格和镜像，平台按训练 Attempt 创建实例。通过可恢复的远程任务通道执行训练、收集日志并处理取消。
- 将固定版本输入传到云端并校验；训练成功后将必需产物回传并校验 MinIO、登记可用版本，再释放训练实例并确认云端结果。回传失败保留未同步输出，实例清理失败保留关联和重试入口。云实例状态、训练退出与产物同步状态分别记录。
- 实现真实执行器、运行前检查、进程监控和资源回收。
- 训练失败/取消不发布部分 Adapter；核实远程训练停止后删除实例、核实云端释放。保留已取得日志并标记缺失；成功训练的产物同步失败继续保留实例以恢复回传。
- 保存可核验的 Best/Final Adapter、训练配置和任务来源信息；Best 按真实有效验证 Loss 最低的已保存 Checkpoint 选择，Final 对应最终输出，两者分别登记并持久化。
- 采集并展示真实训练 Loss 与验证 Loss，关联 step/epoch 和已保存的拆分；暂无或采集失败如实展示。
- 从 MinIO 下载并校验数据集与托管模型；优云公共基座直接读取外部目录并固化完整文件内容指纹，见 [ADR-0002](adr/0002-external-readonly-base-models.md)。将 Adapter 和需保留的输出上传、校验 MinIO 后登记为可用产物。

验收：从产品页面选择实际可用模型、单 GPU 规格和镜像，在该真实组合完成一轮受控小样本文本 SFT＋LoRA；记录所选身份、版本、训练参数、实际 GPU/显存与峰值占用，核对固定拆分和真实训练/验证 Loss、Best/Final 指标与文件关联；从 MinIO 重新下载两种 Adapter 后可加载，上传失败的产物不得标记为可用或销毁唯一输出；必需产物可用后训练实例释放结果可核验。

## 5. 模型管理与推理服务

- 完整目录上传按文件恢复；ModelScope/Hugging Face 公开模型导入记录解析后的版本、进度、取消与重试状态。正式托管文件保存并校验 MinIO，优云公共基座单独引用，不重复上传。
- 登记 MinIO 托管模型与训练产物，验证对象索引和校验和；优云公共基础模型登记外部只读来源和内容指纹。
- 实现 vLLM 创建、启动、健康检查、请求转发、停止和日志。
- 用户发起试用时创建独立优云 GPU 实例并运行 vLLM，在 ModelForge 内验证本次训练产物；训练实例释放确认后才申请推理 GPU，避免超过首版单 GPU 边界。提供手动结束，并由后端在无进行中的请求、空闲 15 分钟后删除推理实例；关闭页面继续计时，再次试用重新创建。
- 确保推理服务使用明确选定的模型版本。
- 提供当前页面内微调模型的多轮文本流式对话和停止生成，用户选择 Best/Final，显示基础模型和 Adapter 版本；停止生成须核实远程请求结束，不立即删除实例。刷新后为空会话，对话历史持久化和基础模型并排对比后置。
- 服务启动前从 MinIO 恢复所选 Adapter；基础模型按来源恢复托管文件或读取优云公共目录，核对与训练时相同的内容身份后再加载，不能依赖旧训练磁盘。

验收：原训练实例已释放后，可从 MinIO 在独立新建的推理实例加载本次产物，平台内至少两轮真实对话能携带上下文并核实基础模型/Adapter 绑定；手动结束和空闲回收分别确认进程退出及实例删除，覆盖关闭页面、生成中与 Worker 重启。再次试用可新建实例恢复同一产物。失败启动可诊断且不遗留子进程，云资源回收结果分别核实。
