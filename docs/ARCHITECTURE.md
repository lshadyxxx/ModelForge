# 运行架构与数据归属

本文记录 ModelForge 已确定的运行拓扑和数据归属。代码布局、模块对外契约与依赖规则统一见 [项目结构设计](PROJECT_STRUCTURE.md)。本地基础骨架已实现；训练、推理、任务调度及云接入仍是目标架构，实现状态见[运行与验收](RUNNING.md)。

## 产品首版的远程执行边界

2026-10-28 用户要求增加优云 API 工作流，范围决策见 [ADR-0001](adr/0001-ucompshare-remote-execution.md)，已核对的官方能力见[优云能力核对](../<internal-evidence>)。这是尚待实现的目标，不是部署记录。

```text
浏览器 → 同源 Web / FastAPI → PostgreSQL / MinIO
                 │                ▲
                 ▼                │ 输入版本、任务状态、正式产物
          单平台 Worker ────────────┘
                 ├── 优云资源 API：配置、镜像、模型目录、实例生命周期
                 ├── 远程任务通道：训练/推理进程、日志、取消与退出核对
                 └── 双向文件传输：固定输入 → 云端；产物 → MinIO
                                      │
                               优云单 GPU 执行实例
                               ├── 公共基础模型只读目录
                               ├── 输入运行副本
                               └── Adapter 临时输出 / 推理运行时
                                      │
                         推理响应 → 平台 API → 浏览器对话
```

控制面继续用本地 Compose，API 与 Worker 共用后端代码并独立运行。用户从界面选择基础模型、单 GPU 规格和镜像，不在规格阶段硬编码特定型号。Worker 按训练 Attempt 创建关联的优云实例；已有实例不作为首版训练前提。具体采用官方远程任务 CLI、SSH 或其他经验证通道仍待锁定，不假设资源 OpenAPI 自带托管训练接口。PostgreSQL 保留实例、远程任务和平台 Attempt 的关联及操作状态；MinIO 保存正式数据集、托管模型与产物。优云公共基座采用外部只读引用，见 [ADR-0002](adr/0002-external-readonly-base-models.md)；其他云端文件属于运行副本或待回传输出，未经回传及校验的输出保持未同步状态。

Worker HTTP 存活、云实例 Running、训练进程退出、产物已回收、推理 ready、GPU 租约释放与实例停止/删除分别判定。断线不能当作远程进程已退出；回传失败不能将产物标记可用或销毁唯一输出。推理页由平台 API 访问优云实例上的运行时；ModelVerse 托管自有权重接口当前未证实，仍作为待核对能力。

训练成功后，必需产物写入并校验 MinIO、登记为可用版本，随后释放训练实例并查询确认结果。用户发起试用时，再创建独立的单 GPU 推理实例，从正式资产准备基础模型及本次 Adapter，启动 vLLM；推理不依赖原训练实例磁盘。训练与推理仍受同一单 GPU 互斥边界约束，训练实例释放确认前不申请推理 GPU。推理支持手动结束，并在无进行中的请求、空闲 15 分钟后由后端自动删除实例；关闭页面后继续计时，再次试用重新创建，正式资产保留。计时、重启对账及失败规则见[产品规格](../<internal-evidence>)。

## 本地运行参考拓扑

以下说明原有本地执行方式；第一阶段只落实控制面基础骨架，产品首版真实 GPU 执行按上方优云边界及后续规格实现。

```text
浏览器
  │ 同源 HTTP / SSE
  ▼
Nginx（生产静态托管与反向代理）/ Vite dev server（本地开发）
  │ /api、/events
  ▼
FastAPI API 进程 ───────────── PostgreSQL
  │                               │
  ├── 文件读写 ── MinIO           │ 任务、attempt、租约、服务状态
  │                               │
  └── 任务状态查询/取消            │
                                  │ 原子领取、心跳、状态更新
                                  ▼
                         独立 Worker 进程
                           ├── 训练执行器 → 训练子进程
                           └── 推理管理器 → vLLM 子进程
                                  │
                                  ├── MinIO：读取输入、保存正式产物
                                  └── 本地工作目录：缓存和临时文件
```

浏览器不连接 PostgreSQL 或 MinIO。FastAPI 是平台业务读写入口，MinIO 访问密钥只保存在后端环境中。Vite 开发代理与生产反向代理提供同源 `/api` 路径；日志和进度首期通过 SSE 推送，控制操作继续使用 HTTP。

API 与 Worker 共用 Python 包但独立启动。API 负责快速请求、参数校验和状态查询；Worker 通过执行器管理训练与推理生命周期，云端执行时核对远程任务事实。PostgreSQL 任务表作为首期队列，单 Worker 原子领取任务并更新租约和心跳，不先引入 Redis。

## 核心业务模块

| 模块 | 负责的概念和规则 |
|---|---|
| `datasets` | 数据集及不可变版本、校验、发布和引用保护。 |
| `training` | 用户训练任务、每次独立 attempt、状态转换、取消、重试和日志索引。 |
| `models` | 基础模型与产物版本、MinIO 文件清单、校验状态和来源血缘。 |
| `serving` | 推理服务配置、模型版本绑定、启动状态、健康检查和生命周期。 |
| `resources` | 训练与推理共用的 GPU 租约、原子互斥、续租和释放核对；首期单 GPU。 |
| `overview` | 聚合任务、数据集和推理服务概况，不拥有其他模块的写规则。 |

`Task` 表示用户提交的一项训练目标；`Attempt` 表示该目标的一次执行。重试创建新的 Attempt。托管模型版本须在 MinIO 文件上传并验证完成后才可用；外部只读基座则按来源、完整文件清单和内容指纹核对，目录路径不等于版本。`InferenceService` 绑定明确的基础模型身份和 Adapter 版本；进程存在不代表服务 ready，ready 需通过健康检查和最小推理请求确认。术语见 [GLOSSARY.md](../GLOSSARY.md)。

训练与推理共享首期单 GPU 资源租约。云端停止或取消先核对远程运行时退出，再删除实例并核实云端释放结果，最后释放匹配租约。失败/取消不发布部分 Adapter；成功训练的产物回传失败仍保留实例恢复回传。训练退出成功、产物可用、服务 ready 和资源释放是独立状态事实。

## 代码组织

完整目标目录与分阶段创建清单见 [项目结构设计](PROJECT_STRUCTURE.md)。

- 前端按 feature 聚合业务页面、请求及交互；通用能力放在 `shared/`。
- 后端按业务组织模块，模块拥有自己的用例、状态规则及持久化；技术接入放在 `infrastructure/`。
- API 和 Worker 入口放在 `entrypoints/`，通过 `bootstrap.py` 装配依赖；Worker 调用与 API 共用的模块契约。
- GPU 租约统一归 `resources`；文件读写机制和数据集、模型的业务可用性规则分别归属。

首期按实际功能创建文件，避免空壳微服务、重复状态机或只做转发的抽象层。

## 数据归属

- **PostgreSQL** 保存实体、任务及服务状态、租约、版本关系、bucket/object key、SHA-256、大小、错误阶段及外部基座来源与内容指纹。Compose 将其自身的数据目录绑定挂载到 `docker-db/postgres/`。
- **MinIO** 管理正式数据集、用户上传/模型平台导入的托管基础模型、Best/Final Adapter、产物 manifest，以及明确要求保留的运行文件。Compose 将 MinIO 自己的数据目录绑定挂载到仓库根目录 `docker-db/minio/`；平台仍通过 MinIO 接口访问对象。
- **优云公共模型目录** 仅作为外部只读基座来源，不要求复制 MinIO；训练与独立推理须核对同一文件内容身份，目录缺失或变化时阻止执行。平台不持有其完整副本，也不删除公共源文件。
- **本地 `.runtime/`** 保存下载缓存、训练工作目录和上传暂存；可在不丢失正式资产的情况下清理。`docker-db/` 是 PostgreSQL/MinIO 容器的本地持久化底层目录，不是应用文件存储后备方案。
- MinIO object key 按数据集版本、模型版本和 attempt 分配，正式资产不可因重试静默覆盖。
- 产物先登记为待处理；全部必需文件上传并校验后才标记可用。数据库和对象删除分别记录并支持失败重试。

## 本地与生产拓扑

根目录 Compose 启动 Web、API、Worker、PostgreSQL 和 MinIO；PostgreSQL、MinIO 分别绑定挂载到 `./docker-db/postgres`、`./docker-db/minio`，仅由各自的数据容器使用。销毁重建应用容器时保留这些主机目录，数据库和 MinIO 对象可以继续使用。`docker-db/` 只提交 `.gitkeep`，数据目录由 Compose 创建并排除出 Git；临时工作目录另存 `.runtime/`。训练与推理运行时按配置启用；Fake Executor 仅验证软件流程，不伪装 GPU 或子进程证据。在无 GPU 环境可用轻量测试进程核实子进程生命周期；实际训练和训练/推理硬件互斥仍须在 GPU 主机验收。生产首期采用相同模块边界和单机 Worker，GPU 运行时安装在 Worker 可访问的执行环境中。

产品首版控制面仅个人本机访问：Web/API 的宿主机入口绑定回环地址；PostgreSQL、MinIO 与 Worker 探针默认只供 Compose 内网使用。对话采用页面内存上下文、流式输出和停止生成，不持久化历史；云端运行时由后端访问，不公开无鉴权推理端口。

Redis、Kubernetes、多机集群调度、其他云 GPU 供应商、视觉/生成式多模态和多租户权限不进入首期架构；优云智算作为首版单一远程执行平台，具体策略继续在产品规格中收敛。
