# ModelForge 项目简述

## 定位

ModelForge（模锻）面向需要管理模型微调和部署过程的开发者，提供从数据准备到推理服务运行的可观察、可追溯工作流。

项目围绕可追溯的模型训练与推理生命周期，独立定义业务模块、数据模型与运行方式。

## 首版范围入口

首版产品范围和六入口动作清单已确认，详见[产品 MVP 规格](../<internal-evidence>)。真实训练产物必须能在平台内完成推理试用；模型输入同时覆盖完整目录上传、ModelScope 和 Hugging Face 公开模型导入，以及优云公共基座外部只读引用。第一阶段基础骨架是产品闭环的前置工程里程碑，骨架或模拟流程不代表 MVP 完成。

已按连续主流程重做[静态原型](../designs/modelforge-mvp/README.md)：四步创建向导、独立任务详情、Best/Final 选择、独立推理准备、对话和回收。连续流程原型已基本确认，旧版 A/B/C 保留对照；基础骨架已开始实现，真实验收范围见[实施记录](implementation/phase-1-2026-10-29.md)。逐动作清单和平台交互调研见[功能清单与交互调研入口](FEATURE_INVENTORY.md)；其中明确区分已有规格、验收约束、工程初始方案和本轮建议。

模型、单 GPU 规格与镜像在功能界面查询并选择，不预设固定型号。训练/上传/对话参数和容量限额作为初始方案，在实现阶段依据真实优云目录、模型/镜像兼容性和传输实测锁定。自有模型目录上传按文件恢复，已校验文件复用、失败文件重传。工作台、数据集、模型、计算环境、训练和推理试用六个入口及动作清单均已确认。

根据用户追加需求，首版加入优云智算资源/镜像/公共模型查询、远程训练、数据与产物双向传输及云端产物推理试用；范围变更原因见 [ADR-0001](adr/0001-ucompshare-remote-execution.md)。

## 用户核心流程

1. 上传 messages JSONL 文本对话数据集，查看按行校验结果并创建不可混淆的数据集版本。
2. 从界面选择基础模型、GPU、镜像与常用/受控高级训练参数，从数据版本固定划分默认 10% 验证集并保存拆分结果，提交文本 SFT＋LoRA 训练任务；首版训练方式固定。
3. 查看排队、准备、运行、成功、失败或取消等状态、实时日志和真实训练/验证 Loss。
4. 检查 Best/Final Adapter、训练/验证指标、配置和源数据的关联；Best 按最低有效验证 Loss 选择。
5. 选择可用的 Best 或 Final 产物创建独立 vLLM 推理实例，查看基础模型/Adapter 版本并进行当前页面内的多轮文本流式对话，可停止当前生成；刷新或关闭后为空会话。
6. 手动结束试用或等待空闲 15 分钟后端自动删除实例；保留任务记录和模型产物的生命周期关系。

## 首期非目标

- 局域网或公网控制台、登录和用户管理；首版限定个人本机访问，云凭据仅由后端环境配置注入。
- 失败/取消任务的部分 Adapter 发布和试用；确认训练停止后回收实例，保留已取得的日志。
- QLoRA、DPO 和全参数训练；首版训练固定为文本 SFT＋LoRA。
- 基础模型与微调模型的并排对比；首版先提供微调模型多轮对话。
- 对话历史持久化、历史会话管理和跨刷新续聊。
- 多租户计费、组织和复杂权限系统。
- 多机、多卡集群调度及 Kubernetes 编排。
- 多云采购与调度、复杂云厂商适配；优云单平台接入按首版范围继续收敛。
- 视觉理解、文生图、文生视频等多模态训练工作流。
- 把模型文件直接存进关系数据库。

## 产品原则

- 任务状态、产物可用性、推理服务就绪性分别建模。
- 任务输入和结果可追溯，模型产物不可被新任务静默覆盖。
- 执行器失败时保留诊断信息，并确保子进程和 GPU 资源得到回收。
- 本地管理功能不应要求用户先拥有 GPU；GPU 能力按需接入。
- 所有环境统一使用 PostgreSQL，避免本地模式与共享模式产生不同的数据行为。
- 正式数据集、用户上传/模型平台导入的模型和训练产物从首期统一接入 MinIO；优云公共基础模型直接读取外部目录，训练与独立推理核对同一内容指纹，见 [ADR-0002](adr/0002-external-readonly-base-models.md)。本地磁盘仅作暂存和可重建缓存，文件索引与血缘由 PostgreSQL 管理。
- Web 使用 React + Vite 单页应用；FastAPI API 与训练/推理 Worker 分进程运行。
