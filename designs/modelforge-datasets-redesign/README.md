状态：`production-integrated`。三套高保真方案共用同一组真实数据结构，可直接在页面顶部切换。用户已确认 C · 审阅工作室，生产实现与验收记录见[数据集审阅工作室实施记录](../../docs/implementation/datasets-review-studio-2026-11-03.md)。

## 三个方案

| 方案 | 组织方式 | 适合场景 | 取舍 |
|---|---|---|---|
| A · 三栏操作台 | 数据集列表、版本列表、详情与样本预览三栏并置 | 日常管理任务多，需要同时查看列表和详情 | 信息利用率高，窄屏需要折叠为顺序布局 |
| B · 版本账本 | 每个数据集是一条账本，版本沿同一轨道展开 | 重点查看 v1 → v2 → v3 的血缘和内容指纹 | 版本关系最直观，单行横向信息较多 |
| C · 审阅工作室 | 整体统计带、数据集树、逐行样本编辑器、质量检查栏 | 先看资产全貌，再逐条检查、修正并派生新版本 | 编辑效率最高，当前选择 |

页面顶部可切换 A/B/C，右侧按钮可切换信息密度和明暗主题。

## 已覆盖的交互

- C 顶部提供整体统计：数据集/版本数、有效样本、MinIO 对象总量、已发布与待发布数、校验异常、同名数据集和链路健康状态。
- 两个同名“客服123”数据集始终显示 `DT-3E1C`、`DT-4323` 等不可变 ID 后缀，不按名称合并。
- 同一 `dataset_id` 的版本归在同一分组；A 显示版本列表，B 显示版本轨道，C 显示版本芯片。
- 上传面板区分“新建数据集”和“追加已有数据集”，并明确显示目标 ID 和下一版本号。
- 追加已有版本使用自绘数据集选择器，不再展开浏览器原生菜单；同名项带“同名”标记，选项同时显示 ID 后缀、版本数、最新版本、有效样本数和发布状态。
- 上传流程包含目标身份、文件大小、逐行校验、拆分、服务端限制和最终提交状态。
- 已发布版本只读；点击“编辑样本”进入派生编辑态，保存模拟生成下一版本草稿。
- C 的样本审阅支持“对话 / JSONL / 校验”三种视图，`↑ / ↓` 可切换物理行，并显示当前样本属于训练集或验证集。
- C 的版本检查显示有效样本、训练/验证拆分、实际验证比例、文件大小、版本血缘和验证集物理行。
- 提供明暗主题、信息密度、搜索、状态筛选、样本上一行/下一行和键盘焦点样式。
- 768px 和 390px 下的数据集与样本索引改为可横向浏览的卡片；当前选择会自动进入可见区域，正文保持完整宽度。
- 桌面、平板与 390px 移动视口均无页面级横向溢出；抽屉在移动端占满可用宽度。

## 样本编辑的产品约束

原型允许编辑消息文本，但不会覆盖已发布版本。正式实现需要把“编辑样本”定义为“基于当前版本创建新草稿”，并新增后端编辑接口、重新计算 SHA-256、重新校验全部物理行和重新生成拆分快照。当前原型不会调用这些接口，也不会写入 PostgreSQL 或 MinIO。

## 文件

- `index.html`：原型入口与方案切换栏。
- `styles.css`：三套布局、明暗主题、响应式样式和交互状态。
- `app.js`：真实数据形态、方案渲染、上传与样本编辑交互。
- `review/`：ego-browser 验收截图。

本目录保留设计选型过程。正式交互已接入 `frontend/src/features/datasets/`，并由真实 PostgreSQL、MinIO API 和 ego-browser 生产页面验收；原型自身仍不写业务数据。
